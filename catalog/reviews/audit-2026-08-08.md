## Cross-cutting patterns

1. **Spec-driven shipping without issue hygiene.** Multiple specs landed with
   code/plan merges but the sub-issues were never closed. Pattern recurs in
   clusters F and E. Suggest: a `close-sub-issues` automation in the spec workflow
   to auto-close issues when sub-spec ADR lands.
2. **Roadmap restructure (#126, v3.5 observability) created drift.** The v3.5
   phase was retroactively inserted, and sub-issues (#109–#124) were filed
   before implementation started. Recommend: only file sub-issues when the
   first implementation PR opens, not at spec time.
3. **Subsumption patterns missed.** #80–#83 → #92, #77–#79 → #84–#86 — parent
   trackers exist but the children weren't linked or marked as sub-issues.
