# RLM fast-gate research spike

> Phase: 2. Type: spike. Ideation approach: cross-domain.
> Filed: 2026-08-06. Sources verified: 2026-08-06.

## Background

Recursive Language Models (RLM) — Zhang, Kraska, Khattab — replace "stuff the context into the prompt" with a recursive call structure that handles large contexts symbolically. The forbidden-pattern registry (#70) and freshness cache (#66) produce enough context that stuffing them into a per-edit prompt becomes expensive. This spike investigates whether an RLM scaffold can replace the conventional per-edit hook loop with a more scalable quality-gate architecture — competing directly with the AST-grep approach (#73). One of #72/#73 will ship based on the spike results.

## Research Summary

- arXiv 2512.24601 (Zhang, Kraska, Khattab): RLM paper — recursive symbolic handling of large context, demonstrated on long-document QA and code-review-style tasks ([arxiv](https://arxiv.org/pdf/2512.24601), verified 2026-08-06).
- PrimeIntellect blog "Prime Agent": productionizing RLM scaffolding for coding-agent contexts ([prime-agent](https://www.primeintellect.ai/blog/prime-agent), verified 2026-08-06).

- Cross-cutting observation #4 from the research report: "RLM scaffold offers a generalizable primitive" for large-context quality gates ([research report](docs/superpowers/research/2026-08-06-freshness-enforced-coding-research.md), verified 2026-08-06).

## Ideation Notes

*cross-domain transfer.* Borrowed from the recursive-programming literature (RLM) and applied to heretek's quality-gate context. The transfer is non-trivial: RLM was demonstrated on long-document QA, not on edit-time code review. The spike validates whether the scaffold transfers — and whether the cost profile beats the AST-grep approach (#73) on the same task set. Novel because it asks "is recursive quality-gate architecture a better primitive than pattern-match quality-gate architecture?" — a question no existing tool asks.

## Scope

- Minimal RLM scaffold wrapper around heretek's hooks substrate: recursively consults the freshness cache (#66) and forbidden-pattern registry (#70) for each edit decision.
- Test bench: same 30 tasks as #73 AST-grep, plus a "huge context" condition where the freshness cache + registry + recent trajectory exceed 50k tokens.
- Metrics: stale-pin rate, deprecated-API rate, latency per edit, cost per edit (proxy: token-equivalents).

## Out of scope

- Productionizing RLM for all of heretek's quality gates.
- LLM-judge comparisons (orthogonal).
- Custom RLM training (uses existing model classes).

## Hypothesis + method

**Hypothesis:** An RLM-scaffolded quality gate reduces stale-pin rate by ≥30% relative to the #73 AST-grep fast-gate on tasks where the freshness cache + forbidden-pattern registry together exceed 50k tokens, at ≤2× the per-edit cost.

**Method:**
1. Implement minimal RLM scaffold: outer LLM call returns "consult subtree" decisions; sub-calls read from caches and return findings.
2. Run on 30 standard tasks + 10 huge-context tasks per model class.
3. Compare against the #73 AST-grep fast-gate on identical tasks (the spec §3 baseline); record single-pass prompt stuffing only as an optional secondary baseline, not as the ship decision.
4. Measure: stale-pin rate, deprecated-API rate, wall-clock, total-token-equivalents.

**Success criteria:**
- Stale-pin rate reduction ≥30% on huge-context tasks.
- Per-edit cost ≤2× the #73 AST-grep baseline on standard tasks.
- Per-edit latency ≤500ms p95 on huge-context tasks.

**Decision deliverable:** ADR-style note recommending either (a) ship RLM scaffold, (b) ship AST-grep (#73) instead, or (c) defer — RLM cost too high for heretek's per-edit loop.
