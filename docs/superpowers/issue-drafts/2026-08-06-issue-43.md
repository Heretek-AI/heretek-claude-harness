# AST-grep fast-gate integration

> Phase: 2. Type: ship. Ideation approach: external-data.
> Filed: 2026-08-06. Sources verified: 2026-08-06.

## Background

The RLM fast-gate (#72) and AST-grep fast-gate (#73) both propose quality-gate architectures that consume the freshness cache (#66) and forbidden-pattern registry (#70). This is the ship-target: a hooks-plugin feature that uses ast-grep as the pattern-matching engine, gated on the #72 spike showing AST-grep is the lower-cost option. If #72 wins, this issue is superseded.

## Research Summary

- Dev.to / ayame0328 describes a static scanner with 93 rules across 14 categories and approximately 2 seconds of runtime; use this as a design and runtime reference for the gate, not as a detection-rate benchmark ([dev.to](https://dev.to/ayame0328/why-ai-generated-code-is-a-minefield-is-trending-and-what-2-months-of-building-a-static-scanner-4fg4), verified 2026-08-06).
- Propelcode's summary of CodeRabbit's analysis reports 89% GPT-5 suggestion accuracy, 75% self-detection, and 20% slopsquatting ([propelcode](https://www.propelcode.ai/blog/emergent-code-review-patterns-ai-generated-code), verified 2026-08-06) — a measurement reference, not a multiplier claim.
- The <50ms p95 figure below is a heretek acceptance target to validate on fixtures; it is not inferred from the dev.to account.

## Ideation Notes

*external-data triangulation.* Three independent observations triangulated: (a) the dev.to scanner's 93-rule/14-category design and approximately 2-second runtime; (b) Propelcode's accuracy, self-detection, and slopsquatting figures; (c) the need to validate ast-grep latency and coverage on heretek fixtures. Combined as a hooks-plugin feature that runs AST-grep patterns from the forbidden-pattern registry (#70) against each edit, gated on the freshness cache (#66) for context. Novel in heretek because it integrates AST-grep as a native hooks-plugin primitive rather than as a standalone linter — quality gates become a runtime hook, not a CI step.

## Scope

- Hooks-plugin feature `ast_grep_fast_gate` invoked on `PostToolUse:Edit`.
- Pattern source: `catalog/forbidden_patterns.yaml` (#70).
- Context source: `catalog/freshness/*.yaml` (#66) for dep-pinning patterns.
- Per-edit latency target: <50ms p95 (heretek acceptance target; validate on the fixture set).
- Sub-100ms integration with the stale-dep intercept (#67).

## Out of scope

- Custom AST-grep rule authoring UI (existing rule syntax is sufficient).
- LLM-judge fallback for ambiguous matches.
- Polyglot beyond Python/JS/Rust (defer; revisit at Phase 3).

## D5 / D7 implications

- **D5:** D15 hooks plugin owns quality gates; this is a new feature in the existing plugin. No D5 overlap.
- **D7:** ast-grep requires first-use vetting before catalog/plugin adoption. Plan B Task 1 records the vetting evidence: `ast-grep/ast-grep` on GitHub, verified 2026-08-06, MIT licensed, 8k+ stars, and audited; carry that record into the shipping ADR.
- **D11:** hooks plugin uses SHA-ride versioning; this feature is additive.
- **D15:** hooks-plugin-as-flagship — fits.

## Suggested catalog.yaml entry shape

```yaml
# catalog/plugins/hooks/commands.yaml (additive entry)
- name: ast_grep_fast_gate
  script: scripts/ast_grep_fast_gate.py
  triggers:
    - PostToolUse:Edit
  consumes:
    - catalog/forbidden_patterns.yaml
    - catalog/freshness/
  default_severity: warn
  latency_budget_ms: 50
```
