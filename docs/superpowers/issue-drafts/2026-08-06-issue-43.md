# AST-grep fast-gate integration

> Phase: 2. Type: ship. Ideation approach: external-data.
> Filed: 2026-08-06. Sources verified: 2026-08-06.

## Background

The RLM fast-gate (#42) and AST-grep fast-gate (#43) both propose quality-gate architectures that consume the freshness cache (#36) and forbidden-pattern registry (#40). This is the ship-target: a hooks-plugin feature that uses ast-grep as the pattern-matching engine, gated on the #42 spike showing AST-grep is the lower-cost option. If #42 wins, this issue is superseded.

## Research Summary

- Dev.to / ayame0328: 2 months building a static scanner on AST-grep surfaced ~70% LLM-emitted stale-code detection at <5% false positives ([dev.to](https://dev.to/ayame0328/why-ai-generated-code-is-a-minefield-is-trending-and-what-2-months-of-building-a-static-scanner-4fg4), verified 2026-08-06).
- CodeRabbit December 2025 analysis: pattern-level gates (regex + AST combined) reduce AI-generated-code issue rate by 1.7×, 2.74× for XSS-class issues ([propelcode](https://www.propelcode.ai/blog/emergent-code-review-patterns-ai-generated-code), verified 2026-08-06).
- ast-grep's published benchmarks (referenced in dev.to post): sub-millisecond per-pattern match on typical Python/JS files.

## Ideation Notes

*external-data triangulation.* Three independent observations triangulated: (a) the dev.to scanner empirical data on AST-grep accuracy/false-positive rates; (b) CodeRabbit's measured pattern-gate impact on AI-generated code; (c) ast-grep's published performance benchmarks. Combined as a hooks-plugin feature that runs AST-grep patterns from the forbidden-pattern registry (#40) against each edit, gated on the freshness cache (#36) for context. Novel in heretek because it integrates AST-grep as a native hooks-plugin primitive rather than as a standalone linter — quality gates become a runtime hook, not a CI step.

## Scope

- Hooks-plugin feature `ast_grep_fast_gate` invoked on `PostToolUse:Edit`.
- Pattern source: `catalog/forbidden_patterns.yaml` (#40).
- Context source: `catalog/freshness/*.yaml` (#36) for dep-pinning patterns.
- Per-edit latency target: <50ms p95 (ast-grep's typical range).
- Sub-100ms integration with the stale-dep intercept (#37).

## Out of scope

- Custom AST-grep rule authoring UI (existing rule syntax is sufficient).
- LLM-judge fallback for ambiguous matches.
- Polyglot beyond Python/JS/Rust (defer; revisit at Phase 3).

## D5 / D7 implications

- **D5:** D15 hooks plugin owns quality gates; this is a new feature in the existing plugin. No D5 overlap.
- **D7:** ast-grep is a vetted runtime dep (already used elsewhere in heretek); no new vetting.
- **D11:** hooks plugin uses SHA-ride versioning; this feature is additive.
- **D15:** hooks-plugin-as-flagship — fits.

## Suggested catalog.yaml entry shape

```yaml
# catalog/plugins/hooks/commands.yaml (additive entry)
- name: ast_grep_fast_gate
  script: scripts/ast_grep_fast_gate.py
  triggers:
    - PostToolUse:Edit
  consumes:
    - catalog/forbidden_patterns.yaml
    - catalog/freshness/
  default_severity: warn
  latency_budget_ms: 50
```
