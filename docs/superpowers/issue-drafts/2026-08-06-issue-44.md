# Model-card profile catalog (`catalog/model_profiles/`)

> Phase: 3. Type: ship. Ideation approach: external-data.
> Filed: 2026-08-06. Sources verified: 2026-08-06.

## Background

Different model classes (Qwen3.6 27B, deepseek-class, etc.) have different freshness-failure profiles. A blanket enforcement policy either over-warns on capable models or under-warns on weaker ones. Model-card profiles codify per-model enforcement settings: which gates fire, at what severity, with what latency budget — so a project can pin enforcement to its actual model class.

## Research Summary

- Tianpan's "Deprecated API trap" maps 145 APIs and estimates 70–90% deprecated usage in AI-generated code; it does not provide the model-class breakdown claimed by the earlier draft ([tianpan](https://tianpan.co/blog/2026-04-17-deprecated-api-trap-ai-coding-agents), verified 2026-08-06).
- arXiv 2406.09834 studies 7 LLMs and 8 Python libraries in a single language (Python); it is evidence for a focused empirical baseline, not a per-language profile breakdown ([arxiv](https://arxiv.org/html/2406.09834v1), verified 2026-08-06).

## Ideation Notes

*external-data triangulation.* Two independent sources triangulated: (a) tianpan's 145 API mappings and 70–90% deprecated-usage estimate; (b) arXiv 2406.09834's study of 7 LLMs and 8 Python libraries in Python. Combined as a profile catalog that maps each model class to an enforcement profile (which gates, which severities). Per-model profiles must be validated with heretek measurements rather than inferred as cross-language or six-class findings. Novel in heretek because it ties enforcement to measured model behavior — connecting heretek's hooks substrate (#37, #43) to the v2-code-quality-issue-set's model-aware quality-pack track (#19).

## Scope

- `catalog/model_profiles/<model-id>.yaml` with fields: `model_id`, `family`, `size_class`, `enforcement_profile` (gate list + severities + latency budgets).
- Initial profiles: Qwen3.6 27B, deepseek-class, plus heretek's current default.
- Hooks plugin reads the active profile (from `heretek.toml`) and configures gates accordingly.
- Validation: profiles reproduce measured per-model-class behavior within ±10%.

## Out of scope

- Auto-tuning profiles from observed behavior (follow-up; defer until profiles have shipped data).
- Per-project profile overrides (future; global profiles first).
- Model-class onboarding automation (manual curation for now).

## D5 / D7 implications

- **D5:** catalog data, not a plugin. Orthogonal to #19 quality-pack; complements it.
- **D7:** profiles cite tianpan/arXiv as context, but every per-model-class field must be traceable to heretek's own measurements or a study that actually reports that field; do not infer missing cross-language or model-profile data.
- **D11:** N/A — catalog is data, not a versioned plugin.
- **Hooks:** hooks plugin reads the catalog; no new hook added.

## Suggested catalog.yaml entry shape

```yaml
# catalog/model_profiles/qwen3.6-27b.yaml (sketch)
model_id: qwen3.6-27b
family: qwen
size_class: small
source:
  - https://tianpan.co/blog/2026-04-17-deprecated-api-trap-ai-coding-agents
  - https://arxiv.org/html/2406.09834v1
verified_date: 2026-08-06
enforcement_profile:
  stale_dep_intercept: warn
  ast_grep_fast_gate: warn
  forbidden_pattern_severity_floor: warn
  max_per_edit_latency_ms: 200
```
