# Stale-dep intercept hook (`scripts/stale_dep_intercept.py`)

> Phase: 1. Type: ship. Ideation approach: failure-mode.
> Filed: 2026-08-06. Sources verified: 2026-08-06.

## Background

Qwen3.6 27B-class models consistently emit dependency versions that reflect their training-time memory of PyPI/npm state, not the current registry state. The freshness index (#36) gives us the forward-looking data; this item is the enforcement layer that intercepts edits before they commit a stale pin. Lives as a D15 hooks-plugin per the hooks-plugin-as-flagship constraint.

## Research Summary

- Cross-cutting observation #1 from the research report: "stale training data is the dominant failure mode" across all sources ([research report §Cross-cutting observations](https://docs.bswen.com/blog/2026-03-17-prevent-ai-hallucinations-outdated-docs/), verified 2026-08-06).
- CodeRabbit December 2025 analysis: AI-generated code produces ~1.7× more issues than human-written code, with dep-version drift a recurring pattern ([propelcode](https://www.propelcode.ai/blog/emergent-code-review-patterns-ai-generated-code), verified 2026-08-06).
- Hakim Ziad: a single directive ("do not rely on training-data knowledge") cut deprecated output 100→0% ([hakim-ziad](https://medium.com/@hakim.ziad/how-to-stop-coding-agents-from-using-stale-versions-473dcea7359d), verified 2026-08-06) — establishes that enforcement at edit-time works when the prompt and the hook agree.

## Ideation Notes

*failure-mode-driven.* Started from the observed failure: "smaller model writes `requests==2.28.0` when 2.32.x is current." The intervention is a sub-100ms hook that reads the freshness index (#36) and warns when a pin in the diff is older than the cached `latest_release_date`. Novel because the hook reads a local forward-looking cache rather than calling a network registry on every edit — the cost profile enables per-edit invocation.

## Scope

- Hook script `scripts/stale_dep_intercept.py` invoked by heretek's hooks plugin (D15) on `PostToolUse:Edit` for files matching `requirements*.txt`, `pyproject.toml`, `package.json`, `Cargo.toml`, `go.mod`.
- Reads `catalog/freshness/<lib>.yaml` (populated by #36) and compares each pin in the diff against `latest_version`.
- Emits structured warning with: lib, current pin, cached latest, days-stale, severity (warn/block).
- Default mode: warn. Block mode opt-in via `heretek.toml` for projects where stale pins must fail CI.
- Sub-100ms per invocation (cache read + diff scan).

## Out of scope

- LLM-driven suggestion of "correct" version (a follow-up issue; deferred — wants the freshness data stable first).
- Polyglot coverage beyond the 4 ecosystems above.
- Auto-fix / auto-bump (that's #46 freshness tokens territory).

## D5 / D7 implications

- **D5:** D15 hooks plugin owns quality gates; this hook lives there, not as a new plugin. No D5 overlap.
- **D7:** no external runtime deps — reads heretek-internal catalog only.
- **D11:** the hooks plugin uses SHA-ride versioning; this hook is a new entry under the existing plugin's `commands[]`, not a new plugin version.
- **D15:** hooks-plugin-as-flagship — explicitly fits.

## Suggested catalog.yaml entry shape

This hook is a sub-entry of the hooks plugin. Reference:

```yaml
# catalog/plugins/hooks/commands.yaml (additive)
- name: stale_dep_intercept
  script: scripts/stale_dep_intercept.py
  triggers:
    - PostToolUse:Edit
  file_globs:
    - "requirements*.txt"
    - "pyproject.toml"
    - "package.json"
    - "Cargo.toml"
    - "go.mod"
  consumes: catalog/freshness/
  default_severity: warn
```
