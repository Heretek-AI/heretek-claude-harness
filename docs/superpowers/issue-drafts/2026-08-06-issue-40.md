# Forbidden-pattern registry (`catalog/forbidden_patterns.yaml`)

> Phase: 2. Type: ship. Ideation approach: external-data.
> Filed: 2026-08-06. Sources verified: 2026-08-06.

## Background

heretek's quality-pack (#19) addresses code-smell patterns at the AST level. The forbidden-pattern registry is the orthogonal layer: project-specific or community-known bad patterns (deprecated APIs, known-insecure idioms, removed stdlib functions) expressed as regex/AST snippets with rationale and source citation. The scanner substrate (`security-monitoring-pipeline-design.md`) consumes the registry; the security-scan workflow flags matches.

## Research Summary

- Tianpan: "Deprecated API trap" documents 30+ high-traffic deprecated patterns across PyPI/npm with community-confirmed removal timelines ([tianpan](https://tianpan.co/blog/2026-04-17-deprecated-api-trap-ai-coding-agents), verified 2026-08-06).
- Dev.to / ayame0328: 2 months of building a static scanner surfaced that AST mining of deprecated patterns catches ~70% of LLM-emitted stale code with <5% false positives ([dev.to](https://dev.to/ayame0328/why-ai-generated-code-is-a-minefield-is-trending-and-what-2-months-of-building-a-static-scanner-4fg4), verified 2026-08-06).
- arXiv 2406.09834: empirical study of LLM-deprecated-API usage across 6 model classes — quantified which patterns appear most frequently ([arxiv](https://arxiv.org/html/2406.09834v1), verified 2026-08-06).
- CodeRabbit December 2025 analysis: pattern-level fixes reduce AI-generated-code issue rate by 1.7× overall, 2.74× for XSS-class issues specifically ([propelcode](https://www.propelcode.ai/blog/emergent-code-review-patterns-ai-generated-code), verified 2026-08-06).

## Ideation Notes

*external-data triangulation.* Four independent sources triangulated: (a) tianpan's pattern catalog; (b) the static-scanner empirical data on AST-mined patterns; (c) arXiv empirical study on deprecated-API frequency; (d) CodeRabbit's measured impact of pattern-level gates. Synthesized as a YAML registry that the existing scanner substrate reads — no new scanner needed. Novel in heretek because it inverts the usual flow: patterns are *cited* with external sources, so the registry self-documents its evidence base and ages out patterns with verifiable expiration.

## Scope

- `catalog/forbidden_patterns.yaml` with at least 50 patterns covering: deprecated stdlib APIs, removed library methods, known-insecure idioms.
- Each entry: `id`, `pattern` (regex or AST), `ecosystem`, `severity`, `source_url`, `verified_date`, `rationale`.
- Scanner substrate (`security-monitoring-pipeline-design.md`) reads the registry and emits findings.
- Quarterly refresh workflow flags stale citations (>12 months since `verified_date`).
- Initial seeding from tianpan's catalog + arXiv 2406.09834 high-frequency patterns.

## Out of scope

- LLM-driven pattern discovery (orthogonal; could be a follow-up issue).
- Auto-fix / auto-rewrite (that's #46 freshness tokens territory).
- Per-project override mechanism (future; community-level registry first).

## D5 / D7 implications

- **D5:** catalog data, not a plugin. No overlap with quality-pack (#19) — they operate at different layers (AST smells vs deprecated-API patterns).
- **D7:** registry contents are evidence-backed; vetting bar is "each entry cites a verifiable source URL with verified-date."
- **D11:** N/A — registry is data, not a versioned plugin.
- **Scanner ownership:** scanner substrate (existing) consumes the registry; no new scanner plugin.

## Suggested catalog.yaml entry shape

```yaml
# catalog/forbidden_patterns.yaml (sketch)
- id: py-deprecated-imp-module
  pattern: '(?<!from )(?<!import )imp\.'
  ecosystem: python
  severity: warn
  rationale: "imp module removed in Python 3.12"
  source_url: https://docs.python.org/3/whatsnew/3.12.html
  verified_date: 2026-08-06

- id: py-deprecated-requests-2.28
  pattern: 'requests==2\.2[0-8]\.\d+'
  ecosystem: python
  severity: warn
  rationale: "requests 2.28.x has known CVE-2024-35195; pin 2.32.x+"
  source_url: https://github.com/psf/requests/security/advisories
  verified_date: 2026-08-06
```
