# Test: adversarial ideation (long-term measurement)

> Phase: cross. Type: test. Ideation approach: (itself — defines adversarial ideation).
> Filed: 2026-08-06. Sources verified: 2026-08-06.

## Background

This issue is one of four long-term measurement instruments for the spec's ideation methodology (per §5 of `2026-08-06-freshness-enforced-coding-roadmap-design.md`). It defines "effective adversarial ideation" — the LLM-as-critic loop approach — and instruments it for measurement over the 24-month roadmap horizon. Per spec §5, no item in the current 18-item set uses adversarial ideation as the *primary* approach; this test sets up the methodology so future spec drafting can use it deliberately.

## Research Summary

- Cross-cutting observation from spec §5: "adversarial ideation operates purely within model internals" — distinguishing it from the other three approaches and motivating why it's measured alongside rather than as the dominant methodology.
- The research report does not cite external sources for adversarial ideation as a freshness-enforcement methodology — it operates on model internals, not external state. This is itself a measurement finding.

## Ideation Notes

*definitional — this test IS the adversarial ideation approach.* Adversarial ideation is the methodology of generating candidate ideas, critiquing with a second agent pass, and refining. This test issue codifies the methodology itself so its effectiveness can be measured over time. It is included in the 18-item set even though no current roadmap item uses it primarily, because §5 of the spec commits to "all four instead of one" — each approach's effectiveness is measured, regardless of current adoption.

## Scope

- Define "effective adversarial ideation" via measurable proxies (below).
- Identify current and future roadmap items that use this approach primarily (current: 0; future: tracked as they appear).
- Track per-item: shipped-on-time, success-criteria met, follow-up issues spawned, downstream adoption.
- Roll up at M12 and M24 with: per-item scorecard + cross-item correlation analysis + methodology-effectiveness verdict.

## Out of scope

- Measuring other ideation approaches (#50, #52, #53 cover them).
- Building tooling for adversarial ideation (this test only measures artifacts produced by it).
- Specifying the M24 roll-up report format.

## Measurement framework

**Definition of "effective ideation" for this approach:**
An adversarial-ideation-produced roadmap item is *effective* iff (a) it ships on time, (b) its success criteria are met without major rework, (c) it spawns ≤1 follow-up issue per shipped item, and (d) it sees ≥1 downstream consumer within 6 months of ship.

**Measurement protocol:**
1. Track current count of items using adversarial ideation as primary (baseline: 0 at M0).
2. As future items using this approach are filed, instrument the same per-item scorecard as #50: ship date, success-criteria pass/fail, follow-up count, downstream adoption.
3. At M12 and M24, report: total count of items using the approach, per-item scorecard, methodology verdict.
4. If count remains 0 at M12, this becomes a signal that adversarial ideation is under-applied — produce a recommendation in the M12 report.

**Success thresholds:**
- If ≥1 item uses adversarial ideation: same thresholds as #50 (≥66% on-time ship, ≥66% success-criteria pass, ≤1.5 follow-ups per item, ≥50% downstream adoption within 6 months).
- If 0 items use adversarial ideation at M24: methodology verdict is "under-applied; spec drafting should consider it more."

**Data collection:**
- Issue tracker for ship dates and follow-up counts.
- Per-item retrospective notes captured at ship time.
- Mid-cycle check-in at M6 and M12.

**Decision deliverable:** M24 methodology-effectiveness report (`docs/superpowers/research/2026-08-06-adversarial-ideation-report.md`) with per-item scorecard (if any items), cross-item analysis, and verdict.
