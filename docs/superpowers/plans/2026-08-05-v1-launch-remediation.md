# v1 Launch Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close all 9 v1 launch-blocker issues (Themes 2, 3, 5) and produce a v1.0 release artifact, so the heretek marketplace can ship publicly with no known gap between catalog state and shipped state.

**Architecture:** One branch per issue, one PR per branch, fixed dependency order. Spec at `docs/superpowers/specs/2026-08-05-v1-launch-remediation-design.md` (commit `1fa9f15`). Three tasks (#12, #21, #13) are hard-gate steps that pause for human action before the next task starts. Tracking issue on GitHub links all 9 sub-issues and is closed at the end.

**Tech Stack:** Python ≥ 3.10 (CI: 3.12), pip, pytest 9.0.3, ruff 0.16.1, jsonschema 4.23.0, PyYAML 6.0.2, ruamel.yaml (for catalog round-trip in Task 2), `gh` CLI for GitHub operations.

## Global Constraints

These apply to every task. Where a task needs additional constraints, they are stated in the task body.

- **D7 vetting bar** (per `mem:conventions`): every approved item satisfies stars ≥ 500, last_commit ≤ 12 months, OSI-approved license, source-audit pass for code-executing components, no critical CVEs in last 24 months.
- **D11 SHA-ride** (per `mem:conventions`): every `items[].sha` is a 40-char hex SHA or the `"first-party-<kind>"` sentinel. Plugin manifest files **never** carry a `version` field. (Marketplace manifest versioning is decided in Task 1.)
- **D15 hooks ownership** (per `mem:conventions`): only the `hooks` plugin may declare hooks. Tasks that touch hook manifests must respect this invariant.
- **D17 catalog as source of truth** (per `mem:conventions`): `catalog/catalog.yaml` is hand-edited; `.claude-plugin/marketplace.json` is generated by `scripts/generate_marketplace.py`.
- **Local gate** (per `mem:task_completion`): every PR must exit 0 on `python scripts/validate.py`, `python scripts/generate_marketplace.py`, `git diff --exit-code .claude-plugin/marketplace.json`, and `pytest -q`. Coverage ≥ 90% on `scripts/refresh_pins.py` for Tasks 2 and 6.
- **Commit style** (per `mem:conventions` + recent commits): Conventional Commits (`type(scope): subject`); scope optional. PR trailer `Closes #N`.
- **YAML** (per `mem:conventions`): lowercase snake_case keys; vetting dates unquoted `YYYY-MM-DD` (PyYAML parses them as `datetime.date` — preserved by ruamel.yaml round-trip in Task 2).
- **Python** (per `mem:conventions`): `from __future__ import annotations` at the top of every module; type hints on public functions; terse one-line docstrings.
- **Tests** (per `mem:conventions`): pytest with `def test_<thing>` snake_case; fixtures in `tests/conftest.py`; per-test `tmp_path` / `monkeypatch` for hermetic CLI runs.

```markdown
# Marketplace Manifest Versioning — Decision

> Date: 2026-08-05. Resolves issue #14.

## Context

D11 pins every plugin's effective version to the marketplace repo commit
SHA. The marketplace manifest itself (`.claude-plugin/marketplace.json`)
does not currently carry a `metadata.version`. Claude Code's
`/plugin marketplace update` flow updates to the latest commit regardless.

This ADR decides whether the marketplace manifest should also carry an
explicit `metadata.version` for human readability / release announcement
purposes.

## Options considered

### A. Add `metadata.version: 1.0.0` and bump per release
- Pro: matches user expectations (a marketplace has a version);
  `gh release create` can stamp it.
- Pro: README / announcement can quote a single canonical version string.
- Con: drift risk — maintainer must remember to bump; CI lint required.
- Con: redundant with the SHA pin (D11 already pins the marketplace).

### B. Keep SHA-only; release is `v1.0.0` tag, not manifest field
- Pro: zero drift risk; manifest stays pure-data.
- Pro: aligns with D11's "version = commit SHA" worldview.
- Con: `gh release create` tag has no in-manifest anchor; humans must
  look at git history or the GitHub Release page for the version.

### C. Hybrid — `metadata.version: "1.0.0 (commit <short-sha>)"`
- Pro: human-readable + SHA-anchored in one place.
- Con: redundant with `metadata.commit` (which Claude Code already
  exposes); requires maintaining a derived field.

## Decision

**Option [A or B] chosen.** Rationale: [one paragraph].

## Consequences

- If A: implementation below in this task; Task 9 stamps `1.0.0` and bumps
  on subsequent releases.
- If B: Task 9 stamps `v1.0.0` tag without changing marketplace.json.
```

```python
def update_shas(catalog_path: Path, *, gh_token: Optional[str]) -> list[tuple[str, str, str]]:
    """Re-fetch upstream HEAD SHA per item and write it back to catalog_path.

    Round-trips via ruamel.yaml to preserve comments (the catalog is hand-edited).
    Returns a list of (item_id, old_sha, new_sha) tuples for items that changed.
    """
    if not gh_token:
        print("error: --update-shas requires --github-token / GITHUB_TOKEN", file=sys.stderr)
        raise SystemExit(2)

    from ruamel.yaml import YAML  # local import — optional dep, only needed here.

    yaml = YAML()
    yaml.preserve_quotes = True
    data = yaml.load(catalog_path.read_text())

    updates: list[tuple[str, str, str]] = []
    for plugin in data.get("plugins", []):
        for item in plugin.get("items", []):
            upstream = item.get("upstream")
            sha = item.get("sha")
            if not upstream or "/" not in upstream or not sha:
                continue
            if str(sha).startswith("first-party-"):
                continue
            repo_meta = _github_get(f"/repos/{upstream}", gh_token)
            default_branch = repo_meta.get("default_branch") or "main"
            ref = _github_get(f"/repos/{upstream}/git/ref/heads/{default_branch}", gh_token)
            new_sha = (ref.get("object") or {}).get("sha")
            if new_sha and new_sha != sha:
                item["sha"] = new_sha
                updates.append((item.get("id", "?"), sha, new_sha))

    if updates:
        with catalog_path.open("w") as f:
            yaml.dump(data, f)

    return updates
```
