## Per-skill summary

### 1. heretek:catalog

- **Modes:** `add-item` (research a candidate third-party item against the D7 bar and append it to an existing plugin's `items[]`) and `add-plugin` (scaffold a brand-new plugin directory + its first items).
- **Pipeline:** research → ADR → catalog update → content file → plugin.json → D15 hook-ownership check → README → validate → atomic commit.
- **Acceptance:** ADR written from SP1 template at `catalog/reviews/<plugin>-<item>.md`; `catalog/catalog.yaml` updated with full vetting block (`status`, `date`, `stars`, `last_commit`, `cve_scan`, `review`); content file written based on `kind` (`skill` / `mcp` / `lsp` / `agent` / `output-style`); `plugin.json` declares new component path with no `version` field (D11 SHA-ride); D15 enforced (no `add-item` adds hook to non-hooks plugin, no `add-plugin` declares hooks); `scripts/validate.py`, `scripts/generate_marketplace.py`, and `pytest` all exit 0; single atomic commit.

### 2. heretek:refresh-pins

- **Scope:** Thin wrapper around `scripts/refresh_pins.py` for the quarterly D7-bar verification workflow.
- **Cadence:** Quarterly (per `SECURITY.md`); immediately on critical CVE; after major upstream releases.
- **Token handling:** Falls back from `GITHUB_TOKEN` env var to `gh auth token` (local `gh` CLI credentials); fails open with `skipped` for every item if neither is available — offline-mode staleness is limited to `vetting.date`.
- **Statuses:** `ok`, `skipped`, `stale_stars`/`stale_commit`/`stale_license`, `cve_alert` (urgent — mark rejected immediately), `license_drift`.
- **Acceptance:** `refresh_pins.py` runs without error; output table is readable; `cve_alert` items triaged immediately (not deferred); stale items get a follow-up commit bumping `sha` + `vetting.date` or moved to `rejected.md`.

### 3. heretek:merge-and-push

- **Scope:** Post-SDD finish-a-development-branch dance.
- **Pre-flight checks (fail fast, no state mutation):** (a) `git status --porcelain` empty; (b) `git rev-parse --abbrev-ref HEAD` returns a branch name (not detached); (c) source branch exists on origin via `git ls-remote`; (d) source branch is an ancestor of target via `git merge-base --is-ancestor`.
- **Steps:** User confirmation prompt → `git checkout main` → `git pull --ff-only` → `git merge <source> --ff-only` → run full local gate on the merged result (`pytest`, `validate.py`, `generate_marketplace.py`, `bash tests/smoke/fast_gate_smoke.sh`) → `git push -u origin <target>` → worktree + branch cleanup (best-effort remote `git push --delete`).
- **STOP invariants:** any test failure, push rejection, or non-FF merge aborts the dance without cleanup. The user is told to pull + rebase + retry rather than the skill force-pushing.
